# SpecWATT

**Энергия под контролем.** Android-приложение, локальный сервер и недорогой ESP32-стенд для мониторинга нагрузки, понятного планирования и безопасной автоматизации.

**Инициатор идеи и руководитель проекта:** [@t1ktakdev](https://github.com/t1ktakdev)
**Разработка и испытания:** команда SpecWATT, Бишкек, Кыргызстан.

> **Статус: инженерный MVP, работающий на серверном симуляторе.** Это не готовое устройство для сети 220 В. Настоящие показания ватт через датчик ещё не подключены, а нативная Android-приёмка не завершена.

## Из чего состоит SpecWATT

| Компонент | Стек | Возможности |
|---|---|---|
| **SpecWATT App** | React Native, Expo SDK 58, TypeScript | RU/KY, первый запуск, DEMO, вход в Brain, главная, устройства, аналитика, автопилот, план, журнал |
| **SpecWATT Brain** | FastAPI, Python, SQLite | Учётные записи и изоляция владельцев, снимки состояния, история, команды, расписания, лимиты и симуляция |
| **SpecWATT Grid** | ESP32, CH340, USB Serial | Прошивка Stage 0 и диагностический мост Stage 1 к Brain, без физических команд и измерений |

## Что уже работает

- **DEMO**: полностью локальный демонстрационный стенд, не нуждающийся в сервере.
- **SERVER / SIMULATOR**: авторизованный FastAPI; выбор своего контроллера, реальные HTTP-запросы, история мощности и событий, пять основных вкладок. Источник данных всегда явно обозначается.
- **Команды**: отправка запросов на CH1/CH2 не означает включения нагрузки; ответ симулятора подтверждается отдельно. Неопределённый результат нельзя автоматически повторять.
- **Расписания**: проверка предложенного окна, создание, отмена и операторский шаг симулятора. Время выбора локальное, при передаче на сервер приводится к UTC.
- **CH3**: защищён, только наблюдение. Никакой пользовательский запрос не может включить канал через интерфейс или сервер.
- **История**: графики показывают поступившие серверные образцы; Wh является расчётной оценкой только покрытых интервалов, а не показанием реального счётчика или обещанной экономией.
- **ESP32**: PING, INFO и STATUS через USB. Мост определяет наличие платы, корректно сообщает обрывы и передаёт диагностическое состояние в локальный Brain через защищённую проверкой владельца ручку. Данные по-прежнему `source: diagnostic`, `measured: false`, `paired: false`. Сервер `/health` сообщает `hardware_transport: false`.

## Структура проекта

- [`mobile/specwatt-app/`](mobile/specwatt-app/) — приложение и клиент FastAPI.
- [`backend/`](backend/) — Brain API, SQLite, расписания и тесты.

## Запуск и проверка

```powershell
git switch integration/unified-v7-20261027
cd mobile/specwatt-app
npm ci
npm test
npm run typecheck
npm run lint
npm run web
```

Для серверных сценариев используйте **отдельную тестовую SQLite-базу** и FastAPI на `127.0.0.1`. Подробности: [backend/README.md](backend/README.md), [product finish runbook](docs/product-finish-20261029/RUNBOOK.md) и [Stage 1 bridge guide](tools/esp32_bridge/README.md).

На текущей интеграции локально проверены 254 мобильных теста, 95 backend-тестов, 104 security-теста и 12 USB bridge-тестов. Это результаты программной приёмки. WEB-скриншоты и Android JS export **не доказывают запуск APK или нативную доступность**.

## Границы безопасности и следующие этапы

Сейчас **нет** сопряжения настоящего контроллера с пользовательским аккаунтом, INA219-измерений, физических включений GPIO или сертификации на 220 В. Stage 1 не перепрошивает ESP32; резервная копия Stage 0 хранится локально, вне репозитория. Реальное выдёргивание и повторное подключение USB пока не проверено.

Остаются задачи: нативная проверка Android, TalkBack, исправление Expo Doctor 19/20, разбор известных npm security advisories, безопасное сопряжение контроллера и Stage 2 с проверенными низковольтными измерениями. Нельзя выдавать симуляцию за аппаратные данные.

**Разработка ведётся в [`integration/unified-v7-20261027`](https://github.com/t1ktakdev/SpecWatt/tree/integration/unified-v7-20261027).** `main` сохраняется отдельно до полноценной приёмки релиза.
