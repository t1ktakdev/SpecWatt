# Rooms & Spaces — модуль помещений

Организация устройств по комнатам для SpecWATT. Модуль — слой организации
поверх существующей модели устройств: он не создаёт вторую модель устройств,
не отправляет команды оборудованию и не меняет разрешения автопилота.

## Что внутри

```
src/features/rooms/
  model.ts      — чистая модель каталога комнат (тип, иллюстрация, имя,
                  строгая валидация восстановления, редьюсер каталога)
  power.ts      — сопоставление устройств и комнат + честная агрегация
                  мощности (exact / partial / none) и планы dispatch
                  для переименования и переноса
  i18n.ts       — названия типов комнат и иллюстраций (RU + KY)
  store.tsx     — RoomsProvider: свой AsyncStorage-ключ specwatt-rooms-v1,
                  сериализованные записи, ошибки хранилища
  art.tsx       — векторные иллюстрации комнат (react-native-svg, палитра
                  Warm Graphite), без растровых ассетов
  fx.tsx        — сдержанные входные анимации на core Animated, отключаются
                  при системном reduce-motion
  components.tsx— карточки комнат, блок мощности, строки устройств,
                  фильтр по комнатам, лист переноса, подтверждения
  screens/      — list.tsx (список), detail.tsx (комната), edit.tsx
                  (создание/редактирование/удаление)
  tests/        — модульные тесты (node --test)
src/app/rooms/  — маршруты Expo Router: вложенный Stack + точка подключения
                  RoomsProvider (index.tsx, [id].tsx, edit.tsx)
```

## Контракт с существующей моделью

Единственный источник правды о комнате устройства — строка `Assign.room`
из `src/specwatt/model.ts`. Модуль:

- **перенос устройства** вызывает существующее публичное действие `assign`
  (`useSpec().assign`) с копией текущего назначения, у которой переписано
  только поле `room`. Имя, изображение и `allowAuto` не трогаются; защита
  CH3 дополнительно принудительно поддерживается редьюсером;
- **переименование комнаты** обновляет каталог и рассылает переносы всем
  устройствам комнаты тем же действием `assign` (см. `renamePlan`);
- **удаление комнаты** удаляет только запись каталога. Назначения устройств
  сохраняются: устройства остаются в приложении и собираются в группу
  «Без помещения» — ничего не разрушается;
- комнаты без записи каталога (например, из демо-данных: «Гостиная»,
  «Тестовый стенд») отображаются как неявные, их можно «сохранить как
  помещение» одной кнопкой.

## Честность мощности

`roomPower` повторяет философию `totalPower` из доменной модели:

- все измерения свежие → точная сумма (`exact`);
- часть недоступна (stale/missing/null) → нижняя оценка `≥ X Вт`
  (`partial`) с явной подписью, что это не точное потребление;
- пригодных измерений нет → `—` (`none`). Ноль никогда не выдаётся
  за точное значение без пояснения.

## Точка подключения

Всё приложение модуля живёт в `src/app/rooms/` и подключается маршрутизатором
автоматически, без правок существующей навигации:

1. `src/app/rooms/_layout.tsx` монтирует `RoomsProvider` (ниже корневого
   `SpecProvider`) и вложенный `Stack`.
2. Внешний вход и фильтр по комнатам добавлены на экран «Устройства»
   (`src/screens/dashboard.tsx`) двумя аддитивными вставками:
   `RoomsEntryCard` (переход на `/rooms`) и `RoomFilterChips`
   (провайдер-независимый фильтр по строкам `Assign.room`).
3. Общий store, `model.ts`, i18n, тема и каталог изображений не изменены.
   Единственные файлы вне модуля и маршрутов, затронутые веткой:
   `src/screens/dashboard.tsx` (вход + фильтр) и `package.json`
   (glob тестов модуля в `npm test`).

```bash
cd mobile/specwatt-app

npm run lint
```

## Границы

- Модуль не отправляет команды оборудованию и не содержит транспорта.
- Демо-данные помечены как демо в интерфейсе; фикстуры тестов изолированы.
- CH3 остаётся защищённым: перенос комнаты не влияет на защиту канала.
- Точность суммы мощности освещается в UI (см. «Честность мощности»).
